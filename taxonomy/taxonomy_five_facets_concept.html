    An Item, Five Facets View

    5F or 5FV. Facets, values, stable IDs
    Version 0.1
    Dusan B. Jovanovic

    This document is the single source of truth for the optional taxonomy extension used to compose the “Item Declaration”: a more detailed description of an item already classified by the DBJ Taxonomy.

    This is a concept behind a template that is used to crate “Five Facets View” aka 5F or 5FV; detailed view attached to an item classified by DBJ Taxonomy. Analogy: shipping log on an shipping container.

    This DOES NOT replace the DBJ Taxonomy, which uses the fixed four-by-four tree. An item is always classified by the DBJ Taxonomy first. Attaching a Five Facets View is optional.

    Facets of Five Facets View (5FV)#

    The 5FV Taxonomy is faceted. Each facet is a closed list of values, and an item gets one value from it. Tags list can have any number of tags.

    FacetValues
    SegmentBusiness, Product, Technology
    DomainBusiness, Information, Application, Technology
    AbstractionConceptual, Logical, Physical
    LifecycleDevelopment, Deployment, Operations
    TagSecurity, Integration, DataManagement

    Domain and Abstraction together form one matrix. An item sits in exactly one cell. This matrix is the format of an Item Declaration.

    Stable IDs#

    It is not the number, the name is the ID. It is immutable and unique. Examples:

    1. IDs are facet-qualified: Segment.Technology is not Domain.Technology.
    2. A matrix cell is Domain.Abstraction, for example Technology.Logical.
    3. A child of a cell appends its name: Technology.Physical.Compute.
    4. A rename is a new ID plus a deprecation of the old one. Never an edit.
    5. Consumers pin a Taxonomy version.

    Reminder: this whole concept is used for when organisation might require detailing and item beyond what simple DBJ Taxonomy Tree, can offer.

    The Matrix#

    This is a classification template. It names the slots and their IDs. It holds no items: what the organization actually has goes into the empty slots, see the example.

    Legend:

    • Dashed border: empty for now. Domain × Abstraction cells are empty until populated, and Tags are dashed because they are applied to items rather than hosting them.
    • Light solid border: facet value.

    Detailing an item classified by DBJ Taxonomy#

    One Segment, one matrix cell, one Lifecycle value, any number of Tags.

    Example: a Kubernetes cluster is Segment.Technology, Technology.Physical, Lifecycle.Operations, Tag.Security.

    Tags apply to items. Items do not live in them.

    IMPORTANT
    Important Taxonomy does not define what the organization actually does or produces. Segment.Product is a slot; the business declares what fills it.

    Vocabulary#

    1. Facets#

    In the context of a content a facet is one way of looking at an item. Each facet answers one question about an item, and has a short, fixed list of possible answers.

    Think of a book in a library. Genre, Language and Year are three facets. Book facets answer one unique classification question: “Genre” and “Language”: they are different questions, about classification facets of an item; a book in the context of library content.

    This Taxonomy is not about library of books, its five facets on each item, answer one unique question each:

    FacetThe classification question it answers
    SegmentWhich part of the organization does it belong to?
    DomainWhat kind of concern is it?
    AbstractionHow concrete is it?
    LifecycleWhich stage is it in?
    TagList of cross-cutting concerns that touch it?

    An item is classified by answering each question once (Tags: as many as apply).
